# План робіт: студент 3 — Feed, Discovery & Public Distribution

Обсяг обмежено завданнями студента 3 у ТЗ. Базова архітектура FastAPI, авторизація, CMS/CRUD редактора, коментарі, опитування та закладки належать іншим учасникам і не змінюються. Поточний репозиторій містить лише README, тому реалізацію слід оформлювати як ізольовані модулі з чіткими точками інтеграції з базовими `Article`/`User` моделями та конфігурацією застосунку.

## Послідовність

1. **Гілка та домовленості.** Працювати у `codex/student-3-feed-discovery-public-distribution`; звірити готові базові моделі/схеми перед інтеграцією. Стек: Next.js 15, React 19, TypeScript, Tailwind CSS; FastAPI, Python 3.12; PostgreSQL 16.
2. **Моделі каталогу.** Додати `Category`, `Tag`, `RSSSource`, `FlashNews` і таблицю зв'язку `article_tags`; узгодити ключі й каскади з `Article` студента 2, не дублювати його модель.
3. **Каталог та пошук.** Реалізувати пагінований `GET /api/v1/articles` із фільтрами категорії/тегів та сортуванням; `GET /api/v1/articles/search?q=...` на PostgreSQL full-text search по заголовку та ліду.
4. **Хроніка та публічна видача.** Додати `GET /api/v1/flash-news` і відкритий `GET /api/v1/public/feed` із пагінацією та стабільною JSON-схемою.
5. **RSS агрегація.** Реалізувати завантаження RSS через `feedparser`, санітизацію HTML та збереження без дублікатів; додати періодичний запуск через APScheduler і керування активністю джерел.
6. **Головна сторінка.** Побудувати адаптивну стрічку: категорії, hero-матеріал, тренди за 24 години, популярні теми, картки й порожній стан пошуку.
7. **Оперативна хроніка.** Додати sidebar timeline та `FlashNewsModal`, прив'язати до API.
8. **Інтеграція та коміти.** Кожен завершений шар фіксувати окремим комітом; перевіряти сумісність із наявною інфраструктурою, коли вона з'явиться. Не реалізовувати функції студентів 1, 2 і 4.

## Поточні передумови й межі

- На момент старту в репозиторії є лише `README.md` і один початковий коміт; бекенд, фронтенд, залежності, міграції та базові моделі відсутні.
- Тому API-модулі студента 3 потрібно проєктувати під інтеграцію з майбутніми базовими `Article` та сесіями БД; не створювати паралельну CMS або власну систему користувачів.
- Формат пагінації публічного API ТЗ не деталізує. До узгодження буде використано просту пару `limit`/`offset` із `items` та `total`.
